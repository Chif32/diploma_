================================================================================
                    ОПИСАНИЕ ДИПЛОМНОГО ПРОЕКТА
              «ChifBoard — веб-приложение для поиска работы»
================================================================================


1. ВВЕДЕНИЕ И АКТУАЛЬНОСТЬ
--------------------------------------------------------------------------------

В современных условиях цифровизации экономики поиск работы всё чаще
осуществляется через интернет. Российские соискатели используют
специализированные платформы (hh.ru, Superjob, Авито Работа и др.), однако
для учебных и исследовательских целей актуально создание собственного
веб-приложения, демонстрирующего полный цикл разработки: от проектирования
базы данных до реализации пользовательского интерфейса.

Дипломный проект «ChifBoard» — это веб-приложение для поиска вакансий,
их публикации и персонального управления избранными предложениями.
Приложение ориентировано на российский рынок труда: вакансии содержат
зарплаты в рублях, города РФ, типичные требования и условия (ТК РФ, ДМС,
график работы и т.д.).

Актуальность проекта обусловлена необходимостью практического освоения
технологий fullstack-разработки: серверной части на Node.js, реляционной
базы данных PostgreSQL и клиентского интерфейса на HTML, CSS и JavaScript.


2. ЦЕЛЬ И ЗАДАЧИ ПРОЕКТА
--------------------------------------------------------------------------------

Цель: разработать работоспособное веб-приложение для поиска и управления
вакансиями с поддержкой регистрации пользователей и личного кабинета.

Задачи:
  • спроектировать и реализовать базу данных для хранения вакансий,
    пользователей и сохранённых объявлений;
  • разработать серверную часть (REST API) на Node.js и Express;
  • создать клиентский интерфейс с разделами поиска, авторизации
    и личного кабинета;
  • реализовать регистрацию и вход пользователей с проверкой данных;
  • обеспечить возможность добавления вакансий в личный кабинет;
  • сформировать каталог актуальных российских вакансий для демонстрации
    поиска по рынку труда РФ;
  • предотвратить повторное добавление одной и той же вакансии.


3. ИСПОЛЬЗУЕМЫЕ ТЕХНОЛОГИИ
--------------------------------------------------------------------------------

Серверная часть:
  • Node.js — среда выполнения JavaScript на сервере;
  • Express — фреймворк для создания HTTP-сервера и REST API;
  • pg — драйвер для работы с PostgreSQL;
  • dotenv — загрузка настроек из файла .env;
  • cors — поддержка кросс-доменных запросов;
  • crypto (встроенный модуль Node.js) — хеширование паролей.

Клиентская часть:
  • HTML5 — разметка страниц;
  • CSS3 — оформление интерфейса;
  • JavaScript (Vanilla JS) — логика в браузере, работа с API через fetch.

База данных:
  • PostgreSQL — реляционная СУБД для хранения данных.

Инструменты разработки:
  • nodemon — автоматический перезапуск сервера при изменении кода;
  • Git — контроль версий.


4. АРХИТЕКТУРА ПРИЛОЖЕНИЯ
--------------------------------------------------------------------------------

Приложение построено по классической трёхуровневой архитектуре:

  [Браузер]  ←→  [Сервер Node.js / Express]  ←→  [PostgreSQL]

  • Уровень представления — статические файлы в папке public/
    (index.html, app.js, styles.css). Интерфейс реализован как
    одностраничное приложение (SPA): переключение между разделами
    («Просмотр вакансий», «Личный кабинет», «Вход») без перезагрузки
    страницы.

  • Уровень бизнес-логики — файл server_clean.js. Сервер обрабатывает
    HTTP-запросы, выполняет авторизацию, проверяет данные и обращается
    к базе данных.

  • Уровень данных — PostgreSQL. Таблицы создаются автоматически
    при первом запуске сервера (функция ensureTables).

Дополнительно используется файл russian_jobs.js — каталог из 40
реалистичных российских вакансий, который отдаётся через API без
обращения к внешним сервисам.


5. СТРУКТУРА ПРОЕКТА
--------------------------------------------------------------------------------

  диплом/
  ├── server_clean.js      — главный файл сервера (точка входа)
  ├── db.js                — подключение к PostgreSQL
  ├── db.sql               — SQL-схема базы данных
  ├── russian_jobs.js      — каталог российских вакансий
  ├── package.json         — зависимости и команды npm
  ├── .env                 — настройки (не попадает в Git)
  ├── .env.example         — шаблон настроек
  └── public/              — клиентская часть
      ├── index.html       — главная страница
      ├── app.js           — логика фронтенда
      └── styles.css       — стили интерфейса


6. БАЗА ДАННЫХ
--------------------------------------------------------------------------------

В PostgreSQL используются три основные таблицы:

  jobs — общий каталог вакансий (публикуемых через форму на сайте):
    id, title, company, location, salary, description, created_at

  users — зарегистрированные пользователи:
    id, username (уникальный), password_hash, created_at

  saved_jobs — вакансии в личном кабинете пользователя:
    id, user_id, title, company, location, salary, description,
    source, external_id, url, created_at, updated_at

Между saved_jobs и users установлена связь «многие к одному»
(ON DELETE CASCADE — при удалении пользователя удаляются его вакансии).

Для ускорения поиска созданы индексы по полям title, company, location
и user_id. Уникальный индекс (user_id, source, external_id) не допускает
дублирование одной вакансии в личном кабинете.


7. РЕАЛИЗОВАННЫЙ ФУНКЦИОНАЛ
--------------------------------------------------------------------------------

7.1. Просмотр и поиск вакансий
  • Поиск по локальной базе (вакансии, добавленные через форму на сайте).
  • Просмотр российских вакансий из каталога (40 объявлений с датами
    до 05.06.2026): IT, медицина, строительство, маркетинг, логистика
    и другие сферы.
  • Фильтрация по ключевым словам: должность, компания, город.
  • Публикация новой вакансии через форму «Добавить вакансию».

7.2. Авторизация
  • Регистрация с проверкой: логин от 3 символов, пароль от 4 символов,
    уникальность логина в базе данных, совпадение паролей при регистрации.
  • Вход по логину и паролю.
  • Выход из аккаунта.
  • Пароли хранятся в виде хеша (crypto.scrypt), не в открытом виде.
  • Сессии реализованы через токены (Bearer) в заголовке Authorization.

7.3. Личный кабинет
  • Кнопка «+» рядом с каждой вакансией добавляет её в личный кабинет
    (только для авторизованных пользователей).
  • Защита от дубликатов: одну вакансию нельзя добавить дважды.
  • Просмотр сохранённых вакансий на отдельной странице с кнопкой
    «Назад к списку».
  • Удаление вакансий из личного кабинета.
  • Навигация между разделами без выхода из аккаунта.

7.4. REST API (основные маршруты)

  Авторизация:
    POST /api/auth/register  — регистрация
    POST /api/auth/login     — вход
    POST /api/auth/logout    — выход
    GET  /api/auth/me        — текущий пользователь

  Личный кабинет (требуется авторизация):
    GET    /api/my-jobs      — список сохранённых вакансий
    POST   /api/my-jobs      — добавить вакансию
    GET    /api/my-jobs/:id  — просмотр одной вакансии
    DELETE /api/my-jobs/:id  — удаление

  Вакансии:
    GET    /api/jobs         — поиск по локальной базе
    POST   /api/jobs         — создать вакансию
    DELETE /api/jobs/:id     — удалить вакансию

  Российский каталог:
    GET /api/russian-jobs    — российские вакансии с фильтрацией


8. БЕЗОПАСНОСТЬ
--------------------------------------------------------------------------------

  • Пароли хешируются перед сохранением в базу (scrypt + соль).
  • Доступ к личному кабинету защищён middleware authMiddleware:
    без валидного токена запрос отклоняется с кодом 401.
  • Пользователь может управлять только своими сохранёнными вакансиями
    (фильтрация по user_id в SQL-запросах).
  • Секреты подключения к БД хранятся в .env, не попадают в репозиторий.


9. ИНТЕРФЕЙС ПОЛЬЗОВАТЕЛЯ
--------------------------------------------------------------------------------

Интерфейс выполнен в современном минималистичном стиле:
  • шапка с навигацией: «Просмотр вакансий», «Личный кабинет», «Вход/Выйти»;
  • карточки вакансий с названием, компанией, городом, зарплатой
    и описанием;
  • метка «Россия» для вакансий из российского каталога;
  • зелёная кнопка «+» для добавления в кабинет (или «✓», если уже добавлена);
  • формы входа и регистрации с вкладками;
  • адаптивная вёрстка для разных размеров экрана.


10. ЗАКЛЮЧЕНИЕ
--------------------------------------------------------------------------------

В рамках дипломного проекта разработано полнофункциональное веб-приложение
ChifBoard для поиска и управления вакансиями. Реализованы все ключевые
требования: авторизация пользователей, личный кабинет, поиск по базе
и российскому каталогу, защита от дубликатов.

Проект демонстрирует практическое применение технологий Node.js, Express,
PostgreSQL и клиентского JavaScript. Архитектура приложения позволяет
расширять функционал: подключение реального API hh.ru, фильтры по зарплате
и городу, роли работодателя/соискателя и др.

Приложение готово к демонстрации на защите диплома и может быть развёрнуто
на любом сервере с установленными Node.js и PostgreSQL.


================================================================================
                    КАК ЗАПУСТИТЬ ПРОЕКТ
================================================================================

1. УСТАНОВИТЬ ПО
--------------------------------------------------------------------------------

  Необходимо установить:
    • Node.js (рекомендуется LTS-версия) — https://nodejs.org
    • PostgreSQL — https://www.postgresql.org/download/


2. СОЗДАТЬ БАЗУ ДАННЫХ
--------------------------------------------------------------------------------

  В PostgreSQL создайте базу данных, например job_board:

    CREATE DATABASE job_board;

  Или через командную строку:

    psql -U postgres -c "CREATE DATABASE job_board;"


3. НАСТРОИТЬ ФАЙЛ .env
--------------------------------------------------------------------------------

  В корне проекта создайте файл .env (можно скопировать из .env.example):

    DATABASE_URL=postgres://user:password@localhost:5432/job_board
    PORT=3000

  Замените:
    user      — имя пользователя PostgreSQL
    password  — пароль
    localhost:5432 — хост и порт (часто порт 5432)
    job_board — имя базы данных


4. УСТАНОВИТЬ ЗАВИСИМОСТИ
--------------------------------------------------------------------------------

  Откройте терминал в папке проекта и выполните:

    npm install


5. ЗАПУСТИТЬ СЕРВЕР
--------------------------------------------------------------------------------

  Обычный запуск:

    npm start

  Запуск с автоперезагрузкой при изменении кода (для разработки):

    npm run dev

  При успешном запуске в консоли появится:

    DB check: tables are ready
    Server running on http://localhost:3000

  Таблицы в базе данных создаются автоматически при первом запуске.


6. ОТКРЫТЬ ПРИЛОЖЕНИЕ
--------------------------------------------------------------------------------

  В браузере перейдите по адресу:

    http://localhost:3000


7. ОСТАНОВИТЬ СЕРВЕР
--------------------------------------------------------------------------------

  Если сервер запущен в текущем терминале:

    Ctrl + C

  Принудительно завершить процесс на порту 3000 (PowerShell):

    Get-NetTCPConnection -LocalPort 3000 -ErrorAction SilentlyContinue |
      ForEach-Object { Stop-Process -Id $_.OwningProcess -Force }

  Или найти PID и завершить:

    netstat -ano | findstr :3000
    taskkill /PID <номер_PID> /F


8. ВОЗМОЖНЫЕ ПРОБЛЕМЫ
--------------------------------------------------------------------------------

  Ошибка «DATABASE_URL is not set»
    → Проверьте, что файл .env существует в корне проекта.

  Ошибка подключения к базе данных
    → Убедитесь, что PostgreSQL запущен и параметры в .env верны.

  Порт 3000 занят
    → Смените PORT=3001 в .env или остановите другой процесс на порту 3000.

  После изменения server_clean.js или russian_jobs.js
    → Перезапустите сервер (Ctrl+C, затем npm start).

  Ошибка «Ошибка при загрузке российских вакансий»
    → Сервер работает со старым кодом — перезапустите его.
