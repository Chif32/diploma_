## 1. ТЕОРЕТИЧЕСКИЕ ОСНОВЫ РАЗРАБОТКИ ВЕБ-ПРИЛОЖЕНИЙ ДЛЯ ПОИСКА ВАКАНСИЙ

### 1.1. Понятие и классификация информационных систем в сфере занятости

Информационная система (ИС) в общем виде представляет собой совокупность данных, технических средств, программного обеспечения и персонала, организованных для сбора, хранения, обработки и выдачи информации в интересах достижения поставленных целей. В сфере занятости и подбора персонала ИС обеспечивают размещение вакансий, поиск кандидатов, ведение резюме, аналитику рынка труда.

По функциональному назначению выделяют:

- **порталы агрегаторы вакансий** (HeadHunter, Superjob, «Работа России») — массовый охват работодателей и соискателей;
- **корпоративные карьерные сайты** — публикация вакансий конкретной организации;
- **учебные и демонстрационные системы** — упрощённые модели для освоения технологий разработки.

По архитектуре различают локальные, клиент-серверные и облачные решения. Современные веб-приложения для поиска работы, как правило, реализуются по схеме «тонкий клиент — сервер приложений — сервер баз данных», что обеспечивает доступ через браузер без установки специализированного ПО на компьютер пользователя.

Ключевые **функциональные блоки** ИС в сфере вакансий:

1. каталог объявлений с поиском и фильтрацией;
2. учётные записи пользователей и разграничение доступа;
3. персональное хранилище избранных вакансий (аналог «откликов» или «избранного»);
4. публикация вакансий работодателем или администратором;
5. администрирование и модерация контента.

В рамках дипломного проекта ChifBoard реализованы блоки 1–4 в объёме, достаточном для демонстрации профессиональных компетенций по разработке программного обеспечения.

|-------------|---------|--------------|-------------|
| Агрегатор | hh.ru, Superjob | Большая база, узнаваемость | Сложность интеграции для учебного проекта |

### 1.2. Современные технологии веб-разработки и архитектура клиент-сервер

Веб-приложение функционирует в архитектуре **клиент-сервер**. Клиентом выступает браузер пользователя, который запрашивает HTML-страницы, таблицы стилей CSS и скрипты JavaScript. Сервер обрабатывает HTTP-запросы и возвращает данные в формате JSON при обращении к программному интерфейсу (API).

**Node.js** — среда выполнения JavaScript на стороне сервера. Её применение позволяет использовать один язык программирования на клиенте и сервере, что упрощает сопровождение небольших проектов. Фреймворк **Express** предоставляет маршрутизацию, middleware и удобную организацию REST API.

**REST (Representational State Transfer)** — архитектурный стиль взаимодействия, при котором ресурсы (вакансии, пользователи) идентифицируются URL, а операции выполняются методами HTTP: GET — чтение, POST — создание, PUT — обновление, DELETE — удаление.

**PostgreSQL** — объектно-реляционная система управления базами данных с поддержкой транзакций, внешних ключей, индексов и ограничений целостности. Для учебного и малых промышленных проектов PostgreSQL является распространённым выбором благодаря надёжности и соответствию стандарту SQL.

На **клиентской стороне** в проекте ChifBoard применяются HTML5, CSS3 и JavaScript без фреймворков (Vanilla JS). Интерфейс организован как одностраничное приложение (SPA): переключение разделов («Просмотр вакансий», «Личный кабинет», «Вход») выполняется без полной перезагрузки страницы за счёт управления видимостью блоков и обращений к API через `fetch`.

### 1.3. Нормативно-правовые и организационные основы рынка труда в Российской Федерации

Деятельность работодателей и соискателей в РФ регулируется Трудовым кодексом Российской Федерации, федеральными законами о занятости населения, о персональных данных (152-ФЗ). При разработке веб-приложения, обрабатывающего учётные записи пользователей, необходимо учитывать требования к защите персональных данных: хранение паролей только в виде хеша, минимизация собираемых сведений (в ChifBoard — логин и хеш пароля).

Содержание вакансий в каталоге проекта отражает типичные для российского рынка условия: заработная плата в рублях, формулировка «на руки», города РФ, упоминание оформления по ТК РФ, ДМС, графиков 5/2, 2/2, гибридного и удалённого формата. Это повышает реалистичность демонстрационных данных для целевой аудитории — российских соискателей.

Государственный портал «Работа России» и коммерческие агрегаторы формируют отраслевые стандарты представления вакансий (поля: должность, компания, регион, зарплата, описание, требования). Проект ChifBoard использует сходную структуру полей, что облегчает восприятие интерфейса.

### 3.2. Разработка серверной части и REST API

Сервер инициализирует Express, подключает middleware `cors`, `express.json`, раздаёт статику из `public/`. При старте выполняется `ensureTables()` — создание таблиц и индексов, если они отсутствуют.

**Аутентификация.** При регистрации пароль хешируется функцией `hashPassword` (scrypt). Проверяется уникальность логина в БД. Генерируется токен сессии, сохраняемый в `Map` на сервере. Middleware `authMiddleware` извлекает токен из заголовка `Authorization: Bearer …` и устанавливает `req.userId`.

**Маршруты личного кабинета.** POST `/api/my-jobs` перед вставкой проверяет наличие дубликата по `(user_id, source, external_id)` или по паре title+company. При конфликте возвращается HTTP 409.

**Каталог российских вакансий.** GET `/api/russian-jobs?q=…` возвращает отфильтрованный и отсортированный по дате список из `russian_jobs.js`.

Пример фрагмента логики (описание): при запросе GET `/api/jobs?q=аналитик` формируется SQL с условием `ILIKE` по полям title, company, location, description.

### ПРИЛОЖЕНИЕ В. ИНСТРУКЦИЯ ПО ЗАПУСКУ ПРОЕКТА

**1. Установить:** Node.js (LTS), PostgreSQL.

**2. Создать базу данных:**
```sql
CREATE DATABASE job_board;
```

**3. Создать файл `.env` в корне проекта:**
```
DATABASE_URL=postgres://user:password@localhost:5432/job_board
PORT=3000
```

**4. Установить зависимости и запустить:**
```
npm install
npm start
```

**5. Открыть в браузере:** http://localhost:3000

**Остановка сервера:** Ctrl+C в терминале.

**Принудительная остановка (PowerShell), если порт занят:**
```
Get-NetTCPConnection -LocalPort 3000 -ErrorAction SilentlyContinue | ForEach-Object { Stop-Process -Id $_.OwningProcess -Force }
```

После изменения файлов `server_clean.js` или `russian_jobs.js` сервер необходимо перезапустить.
